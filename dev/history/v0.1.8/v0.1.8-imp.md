# OperationRecorder 0.1.8 計画と報告

## 目的と範囲

[要求](v0.1.8-req.md) R1 の録画エンジンのリファクタリング。動作・外部仕様は変えない。

- 対象：`src/OperationRecorder/Engine/Recorder*.cs`、`Engine/WinUtil.cs`（内部型 `Raw`/`Ev` と Win32 補助）、`Engine/Native.cs`、`Engine/WindowChangeTracker.cs`。
- 対象外：ReportGenerator・Replay・UI・ExternalEvidence・Recording（記録の制御）。events.jsonl・session.json・画像ファイル名・ログ文言・公開メソッドの引数と戻り値。

## 現状の問題

| 箇所 | 問題 |
|---|---|
| `Raw.Type` | 入力種別が `1`〜`10` の数値。意味はコメントだけで、フック・振り分け・ウィンドウ変化の3ファイルに散在 |
| `Ev.Kind` | `"click"` `"wheel"` `"window-open"` 等の文字列を直書き。綴り誤りをコンパイラが検出できない |
| Win32 値 | `0x201` `14` `0x8005` `GetSystemMetrics(36)` `-16`/`0x20` 等が直書き。一部だけコメントで名前を補っている |
| `RecorderDispatch.cs`（781行） | マウス・ホイール・キー・入力欄・手動撮影・取消・要素情報を1ファイルに持つ |
| 重複 | 「操作前後の画像の固定解除」「操作後の撮影予約」「要素情報取得後の送信判定」「タスクバークリックとの関連付け判定」が複数箇所に重複 |

## 方針

1. **入力種別の列挙型** `RawType`（`MouseDown`=1 … `WindowDestroy`=10）。値は従来の番号のまま。
2. **操作種別の定数** `EventKinds`（`Click` `DoubleClick` `RightClick` `MiddleClick` `Drag` `RightDrag` `Wheel` `Key` `Input` `Capture` `WindowOpen` `WindowSwitch`）。保存形式の文字列は同一で、型は `string` のまま（保存・出力・リプレイ側を変えないため）。ウィンドウ観測の `"open"`/`"switch"` は `WindowChangeKinds` 定数にする（`WindowChangeTracker.Observe` の戻り値は従来通り文字列）。
3. **Win32 定数** `N` に `WH_*` `WM_*` `EVENT_*` `WINEVENT_*` `SM_*` `GWL_*` `ES_PASSWORD` `WS_EX_TOOLWINDOW` `LLKHF_*` `DWMWA_*` `MB_*` `MONITOR_DEFAULTTONEAREST` `WM_IME_CONTROL` 等を定義して置換。仮想キーは `VK` 静的クラスに定義する。
4. **キー分類の分離** `IsModifier` `IsPrintable` `IsImeOrLockKey` `IsEditingKey` `KeyText` `VkName` を純粋な静的クラス `KeyClassifier` へ移す（`GetKeyNameText` の代替名だけ OS 呼出し）。
5. **ファイル分割**（`partial class Recorder` のまま）

   | ファイル | 内容 |
   |---|---|
   | `RecorderDispatch.cs` | 振り分けループ・`NewEv`・共通補助（画像の解放、操作後の予約、送信判定） |
   | `RecorderMouse.cs` | クリック・ダブルクリック・ドラッグ・ホイール・マウス位置の要素情報 |
   | `RecorderKeyboard.cs` | キー操作の分類と記録、IME 状態 |
   | `RecorderTextInput.cs` | 入力欄のフォーカスイン/アウト追跡 |
   | `RecorderSnapshot.cs` | 手動キャプチャと直前1手の取消 |
   | `RecorderElementInfo.cs` | `WindowInfo` `Win32Info` `UiaInfo` `SameProcess` `CtName` |

6. **重複の共通化**：`ReleaseFrames(ev)`、`DropAfter(ev)`、`ScheduleAfter(ev, want, ts)`、`CompleteInfo(ev)`、`TaskbarClickExplains(ts)`。ロックの取得範囲と順序は従来と同一に保つ。

## 検証方法

- 改修前（版上げ直後）に Core を実行し、件数・成功数を基準として記録する。
- 各フェーズ後にビルド（警告0）と Core 全件を実行し、件数が基準以上・失敗0・skip0 であることを確認する。
- 録画エンジンの実フック経路は Core では通らない。入力を送らない WindowEvents（専用 fixture への WinEvent 通知）を実行する。実入力を送る Desktop は利用者の画面へ入力するため、実行の可否を利用者に確認する。
- `git diff` で events.jsonl のキー名・値の文字列に変更がないことを点検する。

- P3：回帰確認・差分点検・報告。

## 実施記録

### 計画変更

- P1（定数化）と P2（分割）は同じ箇所を2回書き換えることになるため、1フェーズで実施した。
- `AddPendingAndSend(ev)`（要素情報を先に取り終えた操作を保存待ちへ加えて送信判定）を共通化に追加した。入力欄・手動撮影・ウィンドウ変化の3か所で使う。
- `TrySendLocked` は送信条件の判定を先頭に1回だけ置き、ホイール相殺の判定と通常の送信を分けた（条件式は同値）。

### P0：版上げと基準

- 版：`0.1.7` → `0.1.8`（csproj、tool.json、`AutomationInstanceTests` の版確認、docs/testing.md の版別パス例、docs/version-numbering.md、dev/README.md）。ケース対応表 `test-cases.json` を再生成（339メソッド/551引数行、前版との差分は版番号だけ）。
- このPCの .NET SDK は `C:\Users\lsv\AppData\Local\Microsoft\dotnet-sdk`（10.0.401）にあり、`C:\Program Files\dotnet` はランタイムだけ。試験時はプロセス内だけ `DOTNET_ROOT`/`PATH` を指定した。システム設定は変更していない。
- 改修前 Core：494件成功、失敗0、skip0、ビルド警告0（`logs/baseline-20261118/summary.json`）。

### P1：定数化と分割

| 変更 | 内容 |
|---|---|
| `RawType` 列挙型（WinUtil.cs） | `Raw.Type` を `int` から変更。値は従来の 1〜10 |
| `EventKinds` / `WindowChangeKinds` / `RawButton`（EventKinds.cs 新規） | 操作種別・ウィンドウ変化種別・ボタン番号と保存名。文字列は従来と同一 |
| `N` の Win32 定数、`VK`（Native.cs） | フック・メッセージ・WinEvent・SystemMetrics・スタイル・DWM・MessageBeep・仮想キー |
| `KeyClassifier`（新規） | キー分類・表示名を Recorder から分離した静的クラス |
| RecorderDispatch.cs | 781行 → 78行（振り分けループと共通補助のみ） |
| RecorderMouse / Keyboard / TextInput / Snapshot / ElementInfo（新規） | 216 / 127 / 164 / 117 / 106 行 |
| 共通化 | `ReleaseFrames` `DropAfter` `ScheduleAfter` `CompleteInfo` `AddPendingAndSend` `TaskbarClickExplains`、`MouseMessageType` `WindowEventType` `IsTyping` `FillKeyInfo` `PickTargetByClick` `TryMergeDoubleClick` `UndoCandidate/Pending/Saved` `Ancestors` `IsPasswordEdit` |

動作の同一性で注意した点：

- `ReadInput` のパスワード判定は、短絡評価にすると `NativeWindowHandle` の読取り失敗時の戻り値が変わるため、従来通り先に読む形を維持した。
- Ctrl+Shift の手動撮影は従来 `Vk` 未設定（=0）で、`SnapshotTrigger.Manual`（=0）を明示しただけ。
- ロックの取得範囲・順序、ログ文言、`events.jsonl` のキーと値は変えていない。差分の文字列リテラルは削除側と追加側で102種が一致した。

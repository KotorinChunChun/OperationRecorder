# 手順見出しの生成仕様

見出しは記録の操作種別・UI要素・入力情報から生成する。各テンプレートは共通の`headline`を使用できる。手順番号の書式は`手順 N.`で、見出し文の末尾に句点は付けない。

## 共通の自動生成パターン

次の表は共通`headline`の全パターン。対象名・入力値・キー名・目盛り数は記録ごとに変わる。

| 操作 | 見出し文 |
|---|---|
| クリック | 対象をクリックします |
| ダブルクリック | 対象をダブルクリックします |
| 右クリック | 対象を右クリックします |
| 中央ボタン | 対象をホイールボタンでクリックします |
| ドラッグ | 対象をドラッグします |
| 右ドラッグ | 対象を右ボタンでドラッグします |
| ホイール | 対象でマウスホイールを上／下に回します |
| キー操作：対象名と種類あり | 「名前」種類で キー名 キーを押します |
| キー操作：対象名と種類がそろわない | キー名 キーを押します |
| 通常の入力 | 入力先に「値」と入力します |
| 値を取得できない入力 | 入力先に入力します |
| 長文・複数行の入力 | 入力先に入力します |
| 入力内容の削除 | 入力先を空にします |
| パスワード入力 | 入力先にパスワードを入力します |
| 手動撮影 | 見出し文なし。テンプレートでは手順番号だけを表示 |

ホイールは2目盛り以上の場合、末尾に`(N 目盛り)`を付ける。長文は60文字を超える入力、複数行は改行を含む入力で、実際の内容は本文のコードブロックに表示する。パスワードは値を見出しへ表示しない。

同じイベントに操作と入力の両方がある場合、見出しには操作文を優先し、本文に入力文と操作文を表示する。手直しした見出しは`edits.json`の文章を優先し、任意の文章になる。

## 対象の表記

| 取得できた情報 | 表記例 |
|---|---|
| 名前と種類 | 「登録」ボタン |
| 名前だけ | 「登録」 |
| 種類だけ | 文書領域 |
| 名前と種類の両方が不明 | 画面上の位置 |

種類の日本語表記は次の28種類。複数のUI Automation種別を同じ日本語へ対応付ける場合がある。

ボタン、チェックボックス、ラジオボタン、コンボボックス、入力欄、文書領域、リンク、一覧、一覧の項目、メニュー、メニューバー、タブ、ツリー、ツリーの項目、表、行、見出し、ラベル、画像、ツールバー、ステータスバー、スクロールバー、スライダー、スピンボタン、タイトルバー、ウィンドウ、カレンダー、グループ。

対象名の連続する空白・改行は空白1つへまとめ、前後の空白を除く。40文字を超える名前は先頭40文字と`…`にする。ただしPane・Window・Document・Custom・Group・Textの長い名前は対象名として使用せず、種類だけ、または「画面上の位置」にする。

## 入力先の表記

入力先の名前は`input.name`、`input.label`、`input.automationId`の順に、空でないものを採用する。名前があれば`「名前」欄`、なければ`入力欄`とする。空文字の値は「空にします」、値自体を取得できない場合は「入力します」とする。

## 画面名の情報

各手順の`window.title`が操作したウィンドウのタイトルであり、テンプレートへは`windowTitle`として渡す。手順書全体の記録名やアプリのプロセス名とは別の情報である。

生成処理の正本は`src/OperationRecorder/Engine/ReportGenerator.cs`、操作前後の標準テンプレートは`templates/user.md`。

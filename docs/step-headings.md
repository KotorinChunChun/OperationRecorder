# 手順見出しの生成仕様

見出しは記録の操作種別・UI要素・入力情報から生成する。各テンプレートは共通の`headline`を使用できる。手順番号の書式は`手順 N.`で、見出し文の末尾に句点は付けない。

## 共通の自動生成パターン

次の表は共通`headline`の全パターン。対象名・入力値・キー名・目盛り数は記録ごとに変わる。

| 操作 | 見出し文 |
|---|---|
| クリック | 対象をクリックします |
| ダブルクリック | 対象をダブルクリックします |
| 右クリック | 対象を右クリックします |
| 中央ボタン | 対象をホイールボタンでクリックします |
| マウスの戻るボタン | マウスの「戻る」ボタンを押します |
| マウスの進むボタン | マウスの「進む」ボタンを押します |
| ドラッグ | 対象をドラッグします |
| 右ドラッグ | 対象を右ボタンでドラッグします |
| ホイール | 対象でマウスホイールを上／下に回します |
| キー操作：対象名と種類あり | 「名前」種類で キー名 キーを押します |
| キー操作：対象名と種類がそろわない | キー名 キーを押します |
| 通常の入力 | 入力先に「値」と入力します |
| 値を取得できない入力 | 入力先に入力します |
| 長文・複数行の入力 | 入力先に入力します |
| 入力内容の削除 | 入力先を空にします |
| パスワード入力 | 入力先にパスワードを入力します |
| 手動撮影 | 見出し文なし。テンプレートでは手順番号だけを表示 |

ホイールの操作が2目盛り以上の場合は、見出し文の末尾に`(N 目盛り)`を付ける。60文字を超える入力を長文、改行を含む入力を複数行とし、どちらも入力内容は本文のコードブロックに表示する。パスワードの値は見出しに表示しない。

同じイベントに操作と入力の両方がある場合、見出しでは操作文を優先し、本文には入力文と操作文を表示する。見出しは任意の文章に手直しできる。手直しした場合は`edits.json`に保存された文章を優先する。

## 対象の表記

| 取得できた情報 | 表記例 |
|---|---|
| 名前と種類 | 「登録」ボタン |
| 名前だけ | 「登録」 |
| 種類だけ | 文書領域 |
| 名前と種類の両方が不明 | 画面上の位置 |

種類の日本語表記は次の28種類。複数のUI Automation種別を同じ日本語へ対応付ける場合がある。

ボタン、チェックボックス、ラジオボタン、コンボボックス、入力欄、文書領域、リンク、一覧、一覧の項目、メニュー、メニューバー、タブ、ツリー、ツリーの項目、表、行、見出し、ラベル、画像、ツールバー、ステータスバー、スクロールバー、スライダー、スピンボタン、タイトルバー、ウィンドウ、カレンダー、グループ。

対象名の連続する空白・改行は空白1つへまとめ、前後の空白を除く。40文字を超える名前は先頭40文字と`…`にする。ただしPane・Window・Document・Custom・Group・Textの長い名前は対象名として使用せず、種類だけ、または「画面上の位置」にする。

## 入力先の表記

入力先の名前は`input.name`、`input.label`、`input.automationId`の順に調べ、最初に見つかった空でない値を使う。名前があれば`「名前」欄`、なければ`入力欄`とする。入力値が空文字の場合は「空にします」、入力値を取得できない場合は「入力します」とする。

## 画面名の情報

各手順の`window.title`には操作したウィンドウのタイトルが入り、テンプレートには`windowTitle`として渡す。手順書全体の記録名やアプリのプロセス名とは別の情報である。

生成処理の正本は`src/OperationRecorder/Engine/ReportGenerator.cs`、操作前後の標準テンプレートは`templates/user.md`。

## 「操作前後」テンプレートの表示

標準の`user`テンプレートは`screenHeadline`を使い、共通の見出し文に操作した画面の名前を付ける。

```text
手順 N. 「画面名」画面の「対象名」種類を「操作名」します
```

画面名は各手順のウィンドウタイトルを使用し、前後の空白を除いて連続する空白・改行を空白1つにまとめる。取得できない場合は`画面名不明の画面の`と表示する。記録全体の名前やプロセス名で画面名を推測しない。

「」で囲む操作名はクリック、ダブルクリック、右クリック、ホイールボタンでクリック、ドラッグ、右ボタンでドラッグの6種類。入力・ホイール・キー操作の文には画面名を付け、操作文自体は共通の生成規則を使う。
マウスの戻る・進むボタンは「画面名」画面でマウスの「戻る」ボタンを押します、のように表示する。

| 共通の見出し文 | 操作前後テンプレートでの表示例 |
|---|---|
| 画面上の位置をクリックします | 「販売管理」画面の画面上の位置を「クリック」します |
| 文書領域をクリックします | 「販売管理」画面の文書領域を「クリック」します |
| 「ホーム」一覧の項目をクリックします | 「販売管理」画面の「ホーム」一覧の項目を「クリック」します |
| 「XBOX モード」グループをクリックします | 「販売管理」画面の「XBOX モード」グループを「クリック」します |
| 「Microsoft Search」入力欄をクリックします | 「販売管理」画面の「Microsoft Search」入力欄を「クリック」します |
| 「セルの編集」欄に「a」と入力します | 「販売管理」画面の「セルの編集」欄に「a」と入力します |
| 「リボン タブ」タブをドラッグします | 「販売管理」画面の「リボン タブ」タブを「ドラッグ」します |

操作名はイベント種別から組み立てる。対象名・画面名・入力値に含まれる「クリックします」などの文字列は置換しない。手直しした見出しにも画面名を付けるが、手直し文の文言や括弧はそのまま表示する。

手動撮影などで共通の見出し文が空なら、手順番号だけを表示する。画面名は従来どおり別行の「画面」に表示する。共通`headline`と保存済みの記録・`edits.json`は変更せず、他の標準テンプレートは共通の表記を維持する。独自テンプレートも`screenHeadline`を指定すればこの表示を利用できる。

## ウィンドウの表示・切り替え

`window-open`は`「画面名」画面が表示されます`、`window-switch`は`「画面名」画面に切り替えます`を生成する。通常操作に`windowEvent`が関連付いた場合は、その操作文に表示結果を続ける。タスクバーからの操作や直接の切り替えは、同じ画面名を重ねて前置きしない。対象範囲・文章例・推定の制約は[ウィンドウイベントの仕様](window-events.md)を参照。

# ウィンドウの表示・切り替えの記録

「撮影の設定」の「ウィンドウの表示・切り替え」で、記録するかどうかと、操作前後の画像を撮影するかどうかを設定する。記録は既定で有効で、新しい画面の表示と前面ウィンドウの変更を検知する。

## 撮影モードと対象範囲

| 撮影モード | 記録する画面変化 |
|---|---|
| ウィンドウ固定（Window） | 指定したウィンドウへの切り替え。別ウィンドウのダイアログは対象外 |
| アプリ全体（App） | 指定したアプリのウィンドウの表示と切り替え。同じアプリ内の別画面も含む |
| 操作中のウィンドウ（Active） | 操作対象になるトップレベルウィンドウの表示と切り替え |
| ディスプレイ（Desktop） | 選択したディスプレイに中心があるウィンドウの表示と切り替え |
| 全ディスプレイ（AllDesktops） | 操作対象になるトップレベルウィンドウの表示と切り替え |

記録開始時に既に表示されている画面、記録対象を選ぶクリック、OperationRecorder自身、デスクトップ、タスクバーそのもの、メニューやツールウィンドウは画面表示の手順にしない。ウィンドウが閉じた通知は内部状態の更新に使い、「閉じる」手順を自動で追加しない。ウィンドウタイトルだけの変更やブラウザー内のタブ切り替えは監視の対象外。

## 手順書の文章

| 観測した内容 | 「操作前後」テンプレートの例 |
|---|---|
| ボタン操作の直後に新しい画面が表示 | 「編集」画面の「設定」ボタンを「クリック」します。「設定」画面が表示されます |
| タスクバーの操作後に対象画面を確認 | タスクバーから「販売管理」を「クリック」します。「販売管理」画面が表示されます |
| 直接ウィンドウを切り替えた | 「一覧」画面に切り替えます |
| 対応する操作が見つからず、新しい画面の表示を観測 | 「確認」画面が表示されます |

画面名には記録したウィンドウタイトルを使う。名前を取得できない場合は「画面名不明の画面」と表示する。利用者による見出し・本文の手直しは優先する。[共通の見出し生成仕様](step-headings.md)も参照。

## 重複と操作の関連付け

表示と前面の通知は200msの確定待ちでまとめ、表示から750ms以内に同じ画面が前面化しても重ねて記録しない。操作後1000ms以内に観測した画面変化は、直近の未保存のクリックやキー操作に関連付ける。関連付けの対象は同じプロセス内での操作と、Alt+Tabなどの切り替え操作に限る。無関係な他アプリの表示は通常のクリックの結果として結び付けない。

操作を保存するまでに、画面変化との関連付けを最大1200ms待つ。関連付けできた画面変化は同じ手順の結果として保存し、重複した手順を追加しない。タスクバーを左クリックしたときは名前と位置を一時的に保持し、1000ms以内に対象範囲内の画面が表示されるか前面に出た場合だけ、その操作を文章に含める。ドラッグや対象外への切り替えだけではタスクバー操作を保存しない。

関連付けは時間的な近接と対象関係に基づく推定であり、OSから「このクリックが原因」と保証されるものではない。1000msを超えた起動や非同期の変化は、表示・切り替えだけの独立した手順になる。スクリーンショットは選択した撮影モードの範囲を保ち、タスクバーまで撮影範囲を拡張しない。

## 保存データとリプレイ

独立した観測は`kind=window-open`または`window-switch`で保存する。操作に関連付いた場合は元の`kind`を保持する。どちらも`windowEvent`に表示/切り替えの区別、遷移先のwindow情報、観測時刻、origin、relationを保存する。

`origin`は`action`（通常操作後）、`switch`（直接の切り替え）、`taskbar`、`window`（観測だけ）。`relation=observedAfterInput`は操作後に観測したことを示し、因果関係の確定を意味しない。見出しと本文の手直しは従来の`edits.json`に保存する。

リプレイ変換では独立した観測を対象画面の`wait`へ変換する。タスクバーからのアプリ起動操作は自動生成しないため、起動が必要ならconfigの起動手順や実行前の準備へ明示する。関連付いた操作の後に別ウィンドウが表示された場合、その画像を操作元の座標で照合せず、後画像の自動条件から除外する。遷移先の待機・画像条件が必要ならconfigへ明示する。

## 検知方式と確認範囲

Windowsの[SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)で、[前面変更・表示・破棄の通知](https://learn.microsoft.com/en-us/windows/win32/winauto/event-constants)を受け取る。コールバックで重い処理をせず、振り分け側で対象判定・情報取得・記録を行う。

CLIでの検証方法は[テスト手順](testing.md)を参照。専用fixture試験ではWinEventの実通知を受け取ることを確認する。タスクバーやAlt+Tabの実入力と、外部アプリごとの動作は別に確認する。
